# F1 2012 시즌 기준형 차량 디자인 100% 구현 계획서

작성일: 2026-07-30
대상: `F1 2012 Season Reference Car` — 2012 시즌 그리드 공통 외관을 결합한 S1 독창 차량
기준 문서: [`F1_2012_DESIGN_REFERENCE.md`](./F1_2012_DESIGN_REFERENCE.md), [`GRAPHICS_RECONSTRUCTION_PLAN.md`](./GRAPHICS_RECONSTRUCTION_PLAN.md)

## 1. 결론

현재 차량은 2012년 F1 시즌 차량의 공통 외관을 읽을 수 있는 1차 기준선을 이미 갖추고 있다. 다음 단계의 목표는 일반적인 오픈휠 차량을 만드는 것이 아니라, **2012 시즌 그리드에서 반복된 설계 문법이 한눈에 보이는 기준형 차량**으로 정리하는 것이다. 부품을 무작정 더하지 않고 정면·측면·후면 기준을 고정해 각 부품의 위치·비율·재질·동작을 측정 가능한 기준으로 잠근다.

이 문서에서 말하는 “100% 구현”은 특정 팀 차량의 픽셀 복제나 실제 CFD·CAD 데이터의 완전한 재현이 아니다. 특정 팀 자산을 복제하지 않는다는 라이선스 경계를 유지하면서, **승인된 2012 F1 시즌 기준 세트의 디자인 체크리스트와 검증 게이트를 100% 통과하는 상태**를 의미한다.

특정 차종 한 대를 100%에 가깝게 재현하려면 별도 차종을 선택하고 정면·측면·후면·상면 기준 이미지와 사용 권한을 추가로 승인해야 한다.

### 1.1 F1 2012 시즌 기준의 의미

기준 세트는 2012 시즌의 다음 12개 차량군을 비교해 추출한다.

`Red Bull RB8` · `McLaren MP4-27` · `Ferrari F2012` · `Mercedes W03` · `Lotus E20` · `Sauber C31` · `Force India VJM05` · `Williams FW34` · `Toro Rosso STR7` · `Caterham CT01` · `Marussia MR01` · `HRT F112`

이 차량들의 로고·색상·스폰서·고유 리버리를 복사하지 않고, 2012 시즌을 식별하게 하는 공통 시각 문법만 추출한다.

- 낮은 노즈 팁과 높은 모노코크가 만드는 스텝 노즈, 그리고 당시의 로우 노즈 예외를 비교 기준으로 사용한다.
- 헤일로가 없는 오픈 콕핏, 헬멧이 노출된 착좌 자세, V8 시대의 에어박스·롤 구조를 유지한다.
- 깊은 사이드포드 언더컷, 코크 보틀 수축, 높은 후방 배기 위치를 2012 시즌의 측면 실루엣으로 고정한다.
- 13인치 휠, 노출된 전·후륜, 다층 프런트 윙, 높은 리어 윙·빔 윙·DRS의 관계를 보존한다.
- 전방 push-rod·후방 pull-rod, 얇은 suspension link, 브레이크 덕트 같은 노출 기계 부품을 시대 판독 요소로 사용한다.

따라서 최종 모델은 “어느 한 팀의 차”가 아니라 “2012 시즌 차량으로 인식되는 S1 기준형”이어야 한다. 사용자가 이후 특정 팀을 지정하면 이 계획의 composite 기준을 버리지 않고 별도 차종 프로필로 분기한다.

## 3. 절대 유지할 경계

- +X는 차량 오른쪽, +Y는 위, -Z는 전방이다.
- 차량 물리는 120Hz fixed-step을 유지하고 렌더러는 읽기 전용 스냅샷만 사용한다.
- 디자인 스튜디오 조작은 `VehicleSimulation`, Rapier, `VehicleControlInput`, AI 상태를 변경하지 않는다.
- 플레이어와 AI의 차량 포즈·속도·타이어 힘을 렌더러가 직접 수정하지 않는다.
- 실제 팀 로고, 스폰서, 드라이버 이름, 번호, 팀 리버리 배열과 복제 트랙 자산은 사용하지 않는다.
- 확인되지 않은 치수·재질·공력 효과는 실제 차량 데이터로 표현하지 않고 `initial_assumption`으로 기록한다.
- 새 production dependency는 추가하지 않는다. GLB 파이프라인이 필요하면 기존 `@react-three/drei` 로더로 해결하고 결정 로그와 자산 등록을 먼저 갱신한다.

## 4. 100% 판정 기준

아래 항목을 모두 통과해야 디자인 완료로 판정한다. 수치 허용 오차는 실제 차량 측정값이 아니라 이 프로젝트의 시각 검증용 `initial_assumption`이다.

### 4.1 형상 기준

- 정면·측면·후면·상면에서 차량의 노즈, 콕핏, 사이드포드, 엔진 커버, 리어 윙의 관계가 기준 오버레이와 일치한다.
- 휠 중심·휠베이스·전후 트랙 폭·차고의 기준점을 하나의 `CarDesignProfile`에서 읽는다.
- 기준 orthographic 캡처에서 외곽 실루엣 편차는 주요 station 기준 ±2.5% 이내를 목표로 한다.
- 주요 부품의 중심점·각도·두께 편차는 해당 부품의 기준 길이 대비 ±3% 이내를 목표로 한다.
- 좌우 대칭 부품은 기준축 대비 위치·회전·스케일 불일치가 없어야 한다.

### 4.2 부품 기준

다음 20개 항목이 디자인 스튜디오에서 독립적으로 식별되어야 한다.

1. 노즈 팁
2. 노즈 스텝 상면
3. 노즈 지지대
4. 프런트 윙 메인 플레인
5. 프런트 윙 플랩
6. 프런트 윙 엔드플레이트
7. 프런트 서스펜션 push-rod
8. 전륜 브레이크 덕트
9. 콕핏 림
10. 시트·헬멧·바이저·팔·스티어링 휠
11. 롤 구조·에어박스
12. 사이드포드 흡입구
13. 사이드포드 언더컷
14. 엔진 커버 코크 보틀
15. 2012년형 고후방 배기 위치
16. 후방 pull-rod
17. 리어 윙 메인 플레인
18. DRS 플랩·리어 윙 엔드플레이트
19. 빔 윙·중앙 지지대
20. 디퓨저 스트레이크·리어 충돌 구조

### 4.3 동작 기준

- 정지: 네 바퀴가 회전하지 않는다.
- 전진: 네 바퀴가 차량 전진 방향과 일치하는 부호로 회전한다.
- 후진: 네 바퀴 회전 부호가 반전된다.
- 조향: 앞바퀴 steering group의 Y축 회전과 rolling group의 X축 회전이 분리된다.
- 차체 yaw: 휠 조향각에 섞이지 않고 부모 차량 그룹만 회전한다.
- Rapier 각속도가 있으면 우선 사용하고, AI 순수 경로에서는 속도·휠 반지름 fallback을 사용한다.
- 화면의 디자인 스튜디오 조향 미리보기는 실제 주행 입력이 아니다.

### 4.4 검토 UI 기준

- 3/4·정면·측면·후면 프리셋이 동일한 차량 상태를 유지한 채 카메라만 전환한다.
- OrbitControls 회전·줌은 차량 물리 상태를 변경하지 않는다.
- 부품별 isolate/show-hide와 부품 이름·설계 의도를 확인할 수 있다.
- 무표식 도장 프리셋은 형상 검토용이며 실제 팀 리버리를 암시하지 않는다.
- 기준 오버레이를 켜면 정면·측면·후면 기준 이미지와 현재 모델을 비교할 수 있다.
- 기준 오버레이는 개발·검토 전용이고 production 주행 화면에는 노출하지 않는다.

## 5. 실행 단계

### Phase A — F1 2012 시즌 기준 세트 잠금

목표는 모델링 전에 무엇을 맞출지 고정하는 것이다.

- 기존 `docs/F1_2012_DESIGN_REFERENCE.md`의 12개 시즌 차량군 관찰 자료를 기준 세트로 선언한다.
- 라이선스가 확인된 개발용 기준 이미지는 [`docs/reference-images/f1-2012/README.md`](reference-images/f1-2012/README.md)의 6개 파일을 사용한다. Google 이미지 검색은 탐색 인덱스로만 유지하고 개별 파일의 원본·라이선스 증명으로 사용하지 않는다.
- 특정 팀을 복제하지 않는 `F1 2012 Season Reference Car`의 최종 설계 선택을 한 장의 설계 시트로 고정한다.
- 기준 시트에 `season_signature` 항목을 두고 스텝 노즈·오픈 콕핏·V8 에어박스·언더컷 포드·고후방 배기·13인치 노출 휠·다층 리어 에어로를 필수로 표시한다.
- 정면·측면·후면·상면의 기준 이미지 또는 직접 작성한 외곽선 도면을 준비하고 출처·라이선스를 기록한다. 로컬 사진은 투시 레퍼런스이므로 상대 비율과 부품 관계 비교에만 사용한다.
- 휠 중심, 노즈 팁, 콕핏 입구, 사이드포드 흡입구, 리어 윙, 디퓨저의 기준점을 표시한다.
- 기준 이미지가 투시 사진이면 치수 도면으로 오인하지 않고 상대 비율만 사용한다.

완료 조건: 기준 이미지 세트, 기준점 목록, 비복제 규칙, 승인된 설계 선택이 문서와 Notion 참조 페이지에 동일하게 기록된다.

### Phase B — 치수·좌표 프로필 분리

모델 geometry 안에 흩어진 숫자를 검토 가능한 데이터로 이동한다.

- `src/world/LowPolyCar.tsx`의 `S1_2012_OPEN_WHEEL_DIMENSIONS`를 확장해 wheel center·station·aero reference point를 하나의 타입으로 묶는다.
- 새 `CarDesignProfile`에 wheelbase, front/rear track, wheel radius, ride height, nose step, cockpit, sidepod, rear aero 기준값을 둔다.
- 물리 치수와 렌더 치수를 분리하고, 렌더 보정에는 `visual_only` 주석을 붙인다.
- 모든 station geometry가 같은 원점·축·단위를 사용하도록 변환 함수를 하나만 둔다.
- geometry 생성 함수가 profile을 받도록 만들어 도장·LOD·시점에 따라 치수가 변하지 않게 한다.

완료 조건: 기준점과 차체 geometry가 단일 프로필에서 나오고, 물리 설정 파일에는 디자인 전용 숫자가 유입되지 않는다.

### Phase C — Hero geometry 100% 구성

현재 저폴리 구조를 기준 오버레이에 맞춰 보정하고 부품 경계를 독립적으로 판독한다.

- 노즈 팁의 낮은 높이와 모노코크 상승 폭을 보정한다.
- 프런트 윙을 메인 플레인·플랩·엔드플레이트·턴잉 가이드·지지대로 분리한다.
- 콕핏의 깊이, 시트 위치, 헬멧 중심, 바이저 경사, 팔·스티어링 휠 높이를 맞춘다.
- 사이드포드 흡입구의 입구·어깨·언더컷·후방 수축을 서로 다른 면으로 만든다.
- 에어박스·엔진 커버 능선·배기 출구·후방 열 배출 면의 높이 계층을 맞춘다.
- 리어 윙, DRS 플랩, 엔드플레이트, 빔 윙, 디퓨저, 후방 충돌 구조를 분리한다.
- 전방 push-rod와 후방 pull-rod 연결점을 휠 중심·기어박스 기준과 정렬한다.
- 브레이크 덕트·허브·타이어 sidewall을 정면과 3/4 시점에서 판독 가능하게 한다.

권장 구현: 현재 프로젝트에서는 procedural geometry를 기준선으로 유지한다. 실제 기준 모델을 도입해야만 오차 기준을 만족할 수 있는 경우에 한해 GLB source-of-truth와 procedural fallback을 별도 결정한다.

완료 조건: 20개 부품 체크리스트가 모두 존재하고, 정면·측면·후면 캡처에서 부품을 이름으로 지목할 수 있다.

### Phase D — 재질·도장·조명

형상 검토를 방해하지 않으면서 2012년형 소재 대비를 만든다.

- 차체 도장, 무광 카본, 타이어, 금속 링크, 바이저, 브레이크 덕트를 별도 material token으로 관리한다.
- bodyColor·accentColor·emissiveColor를 `DesignStudioConfig`에서 관리하고 geometry에 색상 상수를 하드코딩하지 않는다.
- 차체는 중간 roughness, 카본은 높은 roughness, 금속은 낮은 roughness, 타이어는 높은 roughness로 구분한다.
- 실제 팀 색상 조합·로고·스폰서 띠를 복제하지 않고 S1 무표식 그래픽을 사용한다.
- 정면·측면·후면 기준 조명과 주행 조명을 분리해 색상 때문에 실루엣 판정이 달라지지 않게 한다.
- `prefers-reduced-motion`과 저사양 GPU에서 자동 회전·그림자 비용을 낮춘다.

완료 조건: 세 가지 이상의 무표식 도장에서 같은 형상 판정이 유지되고, 기준 조명·주행 조명에서 부품 경계가 모두 읽힌다.

### Phase E — 휠·콕핏·렌더 스냅샷 통합

외관과 물리 상태의 화면 표현을 완전히 일치시킨다.

- `VehicleRenderSnapshot`의 steeringAngleRad·wheelSpinRad 계약을 유지한다.
- `LowPolyCarWheelRefs`의 steering/rolling 부모 구조를 유지한다.
- Driving·Training·Race Weekend·Design Studio가 같은 LowPolyCar wheel contract를 사용하게 한다.
- 영웅 차량은 전체 부품과 운전자를 표시하고, 20대 그리드는 기존 Grid LOD와 shadow 제한을 유지한다.
- 물리 위치·속도·조향을 DOM이나 디자인 패널에서 직접 쓰지 않는다.

완료 조건: 정지·전진·후진·급조향·AI·다차량 화면에서 휠과 차체의 방향·회전·접지가 일치한다.

### Phase F — 디자인 스튜디오를 검증 도구로 확장

현재의 시점·도장·조향 UI를 부품 검토 도구로 확장한다.

- 부품 목록: 노즈, 프런트 윙, 콕핏, 사이드포드, 엔진 커버, 배기, 리어 윙, 디퓨저, 서스펜션, 휠.
- isolate/show-hide, 선택 부품 강조, 부품 설명, 현재 기준값 표시를 추가한다.
- 정면·측면·후면 기준선 또는 반투명 오버레이를 개발 모드에서 제공한다.
- 와이어프레임·flat-shaded·재질 보기 모드를 제공한다.
- 현재 선택 상태와 검토 결과를 JSON으로 내보내되, 물리 상태나 게임 세션을 저장하지 않는다.
- UI 상태는 `DesignStudioConfig`와 패널 로컬 상태에 두고, 시뮬레이션 상태와 공유하지 않는다.

완료 조건: 디자이너가 별도 코드 수정 없이 네 시점과 부품별 상태를 비교하고, 기준 오차를 기록할 수 있다.

### Phase G — LOD·번들·성능 고정

디자인 품질을 올리면서 주행감과 입력 반응성을 희생하지 않는다.

- Hero는 세부 geometry·운전자·기계 링크를 유지한다.
- Grid는 공통 station 차체·간소화된 운전자·휠·기본 공력만 사용한다.
- 20대 차량의 그림자와 재질 수를 제한하고, 디자인 스튜디오만 고품질 shadow를 사용한다.
- Canvas DPR 1.25, basic shadow, antialias 정책을 유지한다.
- `npm run review:performance`의 번들·fixed-step·Rapier·Canvas 계약을 계속 통과시킨다.

완료 조건: hero 기준 캡처 품질이 유지되고 Training·Driving·Race Weekend의 프레임·입력·120Hz 물리 회귀가 없다.

### Phase H — 시각 회귀와 최종 승인

눈으로 “비슷해 보인다”고 판단하는 단계를 끝내고 반복 가능한 증거를 만든다.

- 고정 카메라·고정 조명·고정 viewport에서 정면·측면·후면·3/4 캡처를 생성한다.
- 기준 이미지 또는 외곽선과 현재 모델을 오버레이하고, 편차가 큰 station을 표시한다.
- 기하 체크리스트 20/20, 시점 4/4, 도장 3/3, 휠 동작 5/5, 라이선스 100%를 기록한다.
- 디자인 E2E에서 시점·도장·조향·자동 회전·부품 isolate를 검증한다.
- `npm run typecheck`, 관련 unit tests, `npm run architecture:check`, `npm run build`, `npm run test:e2e`, `npm run verify`를 완료한다.
- 브라우저 실제 확인에서 clipping, floating, shadow 누락, 운전자 가림, wheel axis mismatch를 확인한다.

완료 조건: 검토 표의 모든 항목이 `pass`이고, 실패 항목·허용 오차·참조 출처·남은 가정이 문서와 QA 보고서에 기록된다.

## 8. 완료 판정과 남은 위험

### 완료 판정

다음 조건을 모두 만족할 때만 “차 디자인 100% 구현 완료”라고 표시한다.

1. 20개 부품 체크리스트가 20/20이다.
2. 정면·측면·후면·상면·3/4 기준 검토가 모두 pass다.
3. 휠·콕핏·드라이버·서스펜션·공력 부품의 시각 동작이 스냅샷과 일치한다.
4. 디자인 스튜디오에서 기준 비교·부품 isolate·재질 검토가 가능하다.
5. 물리·AI·입력 경계를 변경하지 않고 전체 `npm run verify`가 통과한다.
6. 모든 외부 자료와 런타임 자산의 라이선스 상태가 기록되어 있다.
7. Notion과 저장소 문서의 기준 세트·변경 이력이 일치한다.

### 남은 위험

- 특정 실제 차량의 CAD·CFD·정확한 텔레메트리가 없으므로 픽셀·공력·주행감의 절대 100%는 보장할 수 없다.
- 투시 사진은 렌즈·카메라 높이·차량 자세에 따라 외곽 비율이 달라진다.
- 고품질 GLB·텍스처를 도입하면 번들 크기와 라이선스 검토 범위가 커진다.
- 차체 부품을 지나치게 세분화하면 20대 그리드에서 draw call과 shadow 비용이 증가한다.
- 시각 기준을 바꾸면 기존 QA 캡처와 E2E 기준선도 함께 갱신해야 한다.
