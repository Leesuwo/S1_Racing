# S1 Racing 전체 그래픽 재구성·수정 기획안

## 1. 문서 목적

현재 S1 Racing의 물리·입력·AI·레이스 세션은 유지하면서, 렌더링 계층을 저폴리 3D와 강한 색 대비 중심으로 재구성한다. 목표는 GTA San Andreas의 특정 자산이나 화면을 복제하는 것이 아니라, 다음과 같은 시각적 특징만 독창적으로 참고하는 것이다.

- 단순하고 읽기 쉬운 저폴리 실루엣
- 넓은 면의 강한 색 대비
- 복잡한 PBR 텍스처보다 색 블록과 명확한 명암
- 과도하게 사실적인 조명보다 따뜻한 환경광과 짧은 그림자
- 작은 화면에서도 차량·도로·연석의 경계가 즉시 보이는 구성

도시형 트랙, 도시 건물, 야자수, 가로등, 외부 지도·차량·캐릭터·브랜드 자산은 범위에서 제외한다. 기존 Northfield GP와 `TEST_TRACK_DATA`의 트랙 데이터만 사용한다.

## 2. 현재 상태와 확인된 문제

### 2.1 현재 작업 트리

현재 작업 트리에는 1차 저폴리 시안이 커밋되지 않은 상태로 남아 있다.

- `src/world/LowPolyCar.tsx` 신규 저폴리 오픈휠 차량 모델(현재 시각 기준선)
- `DrivingScene`, `TrainingScene`, `RaceWeekendScene`의 차량 렌더 교체
- `VisualPalette`, `SceneLighting` 공통 렌더 토큰과 장면 조명
- 세 장면의 노을 계열 배경·조명·카메라와 트랙 색상 조정
- HUD 패널 폭·투명도·반응형 배치 조정
- 도시형 배경 시안은 제거된 상태

이 변경은 물리·입력·세션 로직을 변경하지 않는 것을 전제로 유지하거나 보완한다.

### 2.2 트랙 그래픽 깨짐의 직접 원인

현재 사각 테스트 루프는 전체 잔디 바닥과 전체 직사각형 도로 평면을 같은 높이 `Y = -0.5`에 렌더링한다.

- `TrackGround`가 전체 잔디 평면을 렌더링한다.
- `RectangularTestLoop`가 같은 영역을 덮는 전체 도로 평면을 렌더링한다.
- 두 면이 겹치므로 depth buffer가 앞면을 안정적으로 선택하지 못한다.
- 결과적으로 녹색 사각형과 도로가 깜빡이는 `z-fighting`이 발생한다.

내부 잔디도 별도 평면으로 도로 위에 덮여 있어, 현재 구조는 “도로 링”이 아니라 “전체 사각형을 여러 평면으로 겹쳐 표현하는 방식”이다. 이 구조는 저폴리 스타일을 적용할수록 색 경계가 강해져 문제가 더 눈에 띈다.

### 2.3 구조적 문제

1. 차량 모델이 장면별로 중복되어 외관 변경 시 세 곳을 함께 수정해야 한다.
2. `TEST_TRACK_DATA`와 `NORTHFIELD_GP_DATA`가 서로 다른 도로 렌더 경로를 사용하지만, 고도·바닥·연석의 시각 레이어 규칙은 공통으로 정의되어 있지 않다.
3. 도로, 잔디, 연석, 벽이 동일한 시각 계층으로 취급되어 어느 표면이 위에 있어야 하는지 코드만으로 명확하지 않다.
4. 배경색·안개·조명이 장면 컴포넌트 안에 흩어져 있어 Training·Driving·Race Weekend의 분위기가 쉽게 어긋난다.
5. HUD는 정보량이 많아 카메라를 가까이 당겼을 때 주행 화면을 크게 가린다.

## 3. 시각 설계 원칙

### 3.1 색상 체계

시각 요소마다 역할을 고정한다.

| 요소 | 기본 방향 | 역할 |
| --- | --- | --- |
| 도로 | 짙은 갈색 또는 차콜 | 주행 가능 영역의 중심 |
| 잔디 | 어두운 올리브·녹색 | 도로와 즉시 구분되는 배경 |
| 연석 | 적색·주황색 | 코너 경계와 주행 위험 표시 |
| 벽 | 크림·황토색 | 충돌 경계 표시 |
| 플레이어 차량 | 강한 적색 | 시선의 기준점 |
| AI 차량 | 청록·노랑·보라·연두 | 다차량 구분 |
| 교육 마커 | cyan·amber·violet | AI 관찰 정보 |
| HUD | 검정 반투명 + 고채도 강조색 | 장면 위 정보 계층 |

색상 토큰은 장면별 하드코딩을 줄이고 공통 모듈로 관리한다. 색상 대비는 높이되, 텍스트와 배경의 WCAG 대비를 해치지 않는다.

### 3.2 저폴리 3D 규칙

- 외부 모델 없이 Three.js 기본 geometry를 우선 사용한다.
- 차체는 box·cone·cylinder 조합으로 구성한다.
- 휠은 8면 또는 12면 cylinder를 사용한다.
- 재질은 `flatShading`을 기본으로 하고, 금속성은 작은 범위에서만 사용한다.
- 차량 외관은 물리 스냅샷을 읽기만 하며 위치·속도·회전·접지 상태를 계산하지 않는다.
- 차량 성능을 변경하는 렌더 전용 크기 보정이나 숨은 그립 보너스를 추가하지 않는다.

### 3.3 레이어 높이 규칙

트랙 렌더링은 다음의 명시적 높이 순서를 사용한다.

```text
차량·마커
연석·벽
도로 링
내부 잔디
외부 잔디 바닥
```

모든 높이는 렌더링 전용 상수로 기록하고, 물리 좌표·Rapier collider의 높이를 임의로 변경하지 않는다. 면이 겹치지 않도록 최소 분리값을 정한다. 단위는 m이며 실제 차량·트랙 재현값이 아닌 `initial_assumption`이다.

## 4. 구현 마일스톤

### G0. 시각 기준선 고정

목적: 그래픽 변경 전후를 비교할 수 있는 기준을 만든다.

작업:

- Training·Driving·Race Weekend 초기 화면의 기준 스크린샷 저장
- 카메라 초기 위치, viewport, DPR, WebGL2 조건 기록
- 현재 렌더링 경로와 물리 트랙 데이터 경계를 문서화
- 현재 작업 트리의 1차 저폴리 변경을 보존할지 확인

완료 기준:

- 세 모드에서 동일 조건으로 다시 캡처 가능
- 물리·HUD·렌더링 문제를 서로 구분할 수 있음

### G1. 트랙 렌더링 기반 수정 — 구현 완료

우선순위가 가장 높다. 차량 외관보다 먼저 트랙의 깨짐을 제거한다.

작업:

1. `TEST_TRACK_DATA`용 실제 사각 도로 링 geometry 생성
   - 외곽 사각형과 내부 사각형의 네 변을 각각 쿼드로 생성
   - 전체 도로 평면과 내부 잔디 평면의 중첩 제거
2. `TrackGround`, 도로, 내부 잔디, 연석, 벽의 렌더 높이 분리
3. Northfield 중심선 도로도 같은 높이 토큰과 재질 규칙 사용
4. 연석·벽의 방향과 도로 경계가 데이터 원본과 일치하는지 검증
5. 카메라를 시작점·직선·코너·후방에 배치해 깜빡임과 틈을 확인

완료 기준:

- 녹색 사각형 깜빡임과 면 겹침이 없음
- 도로 링 안쪽에 잔디가 정확히 보임
- 연석·벽이 도로에 떠 있거나 파묻히지 않음
- 물리 판정·리셋 위치·트랙 경계 결과가 기존과 동일함

### G2. 공통 저폴리 오픈휠 차량 모델 — 1차 기준선 구현

작업:

- `LowPolyCar`를 세 장면의 공통 렌더 모델로 사용
- 낮은 노즈·오픈 콕핏·사이드포드·프런트 윙·리어 윙·노출 휠을 공통 구조로 구성
- 헤일로는 사용하지 않고, 시트·엔진 커버·서스펜션 암만 단순화해 표시
- 플레이어와 AI는 색상·스트라이프만 달리하고 기하학적 크기는 동일하게 유지
- Training 차량만 교육용 강조색과 발광을 제한적으로 사용
- 차량 모델의 부모 transform만 물리 스냅샷과 동기화

완료 기준:

- 세 장면에서 차량 실루엣과 색상 규칙이 일관됨
- 차량 렌더 교체가 물리 텔레메트리에 영향을 주지 않음
- 카메라 근거리에서 차체·윙·휠·지면 간 시각적 부유가 없음

### G3. 공통 조명·재질·카메라 — 구현 완료

작업:

- `src/world/VisualPalette.ts` 공통 토큰 모듈 도입
- `src/world/SceneLighting.tsx` 공통 조명 구성을 정의
- 따뜻한 환경광, 보조 하늘광, 제한된 그림자 조합 사용
- 안개 색상과 거리를 세 장면에서 동일한 기준으로 조정
- 추적 카메라가 차량을 가리지 않도록 거리·높이·look-ahead를 재조정
- 도시형 배경이나 불필요한 장식은 추가하지 않음

완료 기준:

- 어느 장면에서도 도로가 배경색에 묻히지 않음
- 플레이어 차량과 AI 차량의 구분이 한눈에 가능
- 카메라 이동 중 심한 clipping·팝핑·깜빡임이 없음
- 그림자와 안개가 프레임률을 과도하게 낮추지 않음

### G4. HUD와 화면 구성 정리 — 1차 구현

작업:

- 현재 HUD의 정보 계약은 보존하고 시각적 계층만 재정렬
- 좌측 텔레메트리 패널의 최대 폭과 투명도를 줄여 주행 시야 확보
- 하단 조작 바가 차량과 결승선을 가리지 않도록 반응형 위치 조정
- Training·Driving·Race Weekend의 강조색은 공통 토큰에서 가져옴
- `aria-label`, 역할, 사용자 동작 텍스트는 유지

완료 기준:

- 기본 viewport에서 차량과 다음 주행 방향이 HUD에 가려지지 않음
- 모바일·좁은 viewport에서도 컨트롤이 겹치지 않음
- 기존 E2E의 텍스트·탭·버튼 계약이 깨지지 않음

### G5. 모드 통합과 회귀 검증 — 진행 예정

작업:

- AI 교육 시작·일시정지·단일 스텝·리셋
- 주행 모드 입력 프리셋·카메라·차량 표시
- 레이스 주말 퀄리파잉·그리드·결과 화면
- 세 모드에서 트랙 렌더링과 차량 모델의 동일성 확인
- 실제 Codex 앱 브라우저에서 초기·주행·결과 화면 캡처

완료 기준:

- `npm run typecheck`
- `npm run test:e2e`
- `npm run architecture:check`
- `npm run verify`

헤드리스 Chromium이 환경 권한으로 시작되지 않으면 Codex 앱 브라우저에서 대체 검증하고, E2E 미실행 상태를 통과로 표시하지 않는다.

## 6. 제외 범위

- GTA San Andreas의 로고, 차량, 캐릭터, 지도, 건물, 사운드, UI 복제
- 도시형 트랙과 오픈월드 배경
- 물리 모델, Rapier collider, AI 제어, 입력 경계 변경
- 실제 차량 제조사·실제 레이스 시리즈의 리버리·브랜딩
- 고해상도 텍스처, PBR 재질, 후처리 효과를 통한 사실적 그래픽 전환
- 그래픽 작업을 이유로 한 엔진 교체

## 7. 주요 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 저폴리 재질이 너무 어두워 차량·도로가 묻힘 | 공통 팔레트와 세 장면 스크린샷 비교로 색 대비 고정 |
| 도로 링 보정이 물리 경계와 어긋남 | 트랙 정의의 bounds·walls·curbs를 단일 원본으로 계속 사용 |
| 그림자·건물 추가로 성능 저하 | 도시 장식은 제외하고, 차량·연석 중심으로 shadow caster 수 제한 |
| HUD가 화면을 가림 | 기본 viewport와 좁은 viewport를 모두 캡처하고 패널 최대 폭 제한 |
| 시각 수정이 물리 버그를 가림 | 각 G 단계마다 기존 물리·레이스 E2E를 함께 실행 |
| 외부 자산 라이선스 문제 | 절차적 geometry를 우선하고 외부 자산은 등록·검토 전 사용하지 않음 |

## 8. 권장 실행 순서

1. G1에서 트랙 링 geometry와 `z-fighting`을 먼저 수정한다.
2. G2에서 공통 저폴리 차량을 확정한다.
3. G3에서 조명·안개·카메라를 세 장면에 통합한다.
4. G4에서 HUD 가림과 반응형 배치를 정리한다.
