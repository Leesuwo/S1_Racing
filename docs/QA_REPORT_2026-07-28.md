## 재현된 문제

### QA-001 — 레이스 결과 전환 E2E 간헐 실패

- 위치: `tests/e2e/smoke.spec.ts:218`
- 테스트 제한: 결과 단계 대기 `30_000 ms`, 테스트 전체 제한도 30초
- 기대: `.weekend-stage`가 30초 안에 `레이스 결과`로 전환
- 실제: 실행에 따라 28.605~33.554초에 전환
- 재현률: 동일 조건 3회 중 2회 실패
- 영향: 기능이 결과 단계에 도달하더라도 30초를 넘으면 CI/완료 게이트가 실패한다.

### QA-002 — 결과 전환 직후 후속 assertion의 시간 예산 부족

반복 실행 중 한 번은 결과 단계가 표시되었지만, 전체 30초 테스트 제한이 먼저 소진되어 `현재 레이스 순위` assertion에서 실패했다. 실패 시 Playwright error context에는 결과 단계와 순위 패널이 모두 표시되어 있어, 선택자 부재보다는 전환 직후 남은 테스트 시간 부족으로 판단한다.

## 비차단 관찰사항

- Rapier 초기화 테스트에서 deprecated initialization parameters 경고가 출력된다.
- 프로덕션 번들 `3,549.95 kB`가 500 kB 경고 기준을 초과한다. 현재 E2E 실패의 직접 원인은 아니다.

## 권장 조치

1. 제품 요구가 결과 단계 30초 이내라면 `RaceSession`의 결과 수렴 시간을 먼저 줄이고, 여러 브라우저 실행에서 30초 이내를 재검증한다.
2. 30초가 하드 요구가 아니라면 테스트 전체 제한을 60초 이상으로 분리 설정하고, 결과 단계 대기와 결과 패널 검증을 별도 assertion 예산으로 둔다.
3. 결과 전환 시점과 참가자별 `finished`·`retired` 상태를 E2E 진단 로그에 남겨 느린 실행의 원인을 구분한다.
4. QA-001을 해결하기 전에는 `npm run verify` 전체 통과로 1차 완성을 재확정하지 않는다.
